# 独立设备接入与校准

## 两条独立通道

按键通道从 AU05 接收器的 HID 集合进入应用。音频通道通过系统录音接口打开用户选中的麦克风。程序使用自身的 HID 监听和手势判定，后台应用、插件、专用预设和厂商网络服务均不参与该链路。

Windows 实测的 USB 型号为 VID FFF1、PID 00DD。与这台接收器匹配的集合如下。接口编号用于定位硬件能力，实体控件和数据包的对应关系需通过实测学习。

| 接口 | 系统 HID 用途页和用途 | 可观察内容 |
| --- | --- | --- |
| MI_02 / COL03 | 0001 / 0006 | 接收器产生的键盘按下、松开 |
| MI_02 / COL02 | 0001 / 0002 | 按钮、滚轮，忽略坐标移动 |
| MI_02 / COL01 | 000C / 0001 | 消费控制集合报告 |
| MI_03 | FFFC / 0001 | 厂商自定义输入报告 |
| MI_00 | USB Audio | 单独枚举的 AU05 麦克风 |

Windows 枚举设备路径，按完整 VID/PID 筛选，注册发现的用途对。在 WM_INPUT 上先读取来源句柄，只有来源属于 AU05 才解开报告正文。捕获窗口在应用处于后台时继续接收消息。接口变化会取消活动动作并重建监听。多个同类接收器造成接口歧义时暂停分派。macOS 通过共享 HID 句柄读取同型号设备，需要单独核对该系统的权限、集合和报告格式。[Windows Raw Input](https://learn.microsoft.com/en-us/windows/win32/inputdev/about-raw-input)

## 厂商按键直控（优先）
 
桌面程序用 HIDAPI 独立打开 FFFC / 0001 集合，定期查询机身在线状态和电量。接收器在线与无线机身在线分别显示。用户启用直控后，程序发起临时会话、保活并订阅实体事件。设备确认订阅或发回有效实体事件后显示直控就绪。校验消息族、槽号及操作码后，K1、K2、K3 和旋钮可直接使用。标准 HID 路径同时停止分派。取消直控、机身离线或程序正常退出时释放订阅，超时丢弃旧会话。程序不改写设备键表。

直控帧编解码与事件识别依据两个公开项目各自记录的 AU05 实测协议；本机对无线机身的验证状态见验收文档。[AU05 Keys 实体事件与会话](https://github.com/elliclee/ulanzi-au05-keys/blob/7819351a5ba5c68874d0519fabe3bf62db47e328/VendorKeys.swift) · [open-vibekey 协议](https://github.com/coopjz/open-vibekey/blob/468cf657ddb100a4f0a594353f82909c9a830aa9/vibekey/protocol.py)

## 标准 HID 校准与分派

每个实体按键样本包含按下与松开，旋转样本包含一次方向脉冲。用户逐个选择角色，分两轮执行同一操作。程序选取两轮均可复现的标准输入集合，过滤厂商心跳和状态包，拒绝冲突或不完整的按键边沿。校准与测试阶段禁止应用执行映射。校准结果单独保存，跨平台或更换不同固件后应重新校准。

正常模式下只有校准匹配的事件进入现有手势状态机。K1 直接开始或结束语音；K2、K3 和旋钮按压产生单击、双击或长按；旋钮转动可以执行滚动或用户绑定的动作。收到同一按键重复按下时，只分派一个按下事件。同一旋钮已按下时，匹配到的旋转归为按住旋转。系统可能同时执行接收器原生的标准键值。

电量查询每 8 秒发送一次。完整电池回报 `81 01 02 11` 的第 11 个字节表示充电状态，0 为未充电，1 为充电中。实测同一台 AU05 在电量均为 100% 时，接线后红灯常亮，该字段从 0 变为 1。仅含电量的短回报不能刷新充电标志。断线、机身离线或完整回报过期后，界面清除充电提示。

机身灯、电量、固件写入和设备配置命令有独立协议。当前版本读取输入和电量，并发送仅在按键直控会话期间生效的订阅控制。电量没有可靠读数时保持未知。接收器在系统中可枚举、设备报告到达、已校准的实体动作、听写最终出字须分别记为不同的测试结果。

## 本地数据边界

原始学习样本仅在校准时收集，两轮匹配后保存该控件的识别模式。USB 实例路径、序列号和麦克风音频不随方案导出。语音使用临时内存，回眸只在用户选择记录且可以确认目标和文本时写入。只读 MCP 客户端经独立授权访问已保存数据，设备输入直接在进程内交付。
