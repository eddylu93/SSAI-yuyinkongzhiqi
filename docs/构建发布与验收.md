# 构建、发布与验收

当前交付为 Windows x64 的 SSAI-语音控制器。用户安装包和完整对应源码位于 release/windows-0.8.1。运行环境为 Windows 10/11 与 WebView2。构建命令和开发依赖见[项目说明](../README.md)。

## 本机证据和剩余验收

0.7.0 的 Windows 安装版读取到 AU05 已连接、电量 90%。在灯光设置中把机身从工作模式切到全灭，返回映射页后四组预览灯均显示灭；切回工作模式后，设备回读和模型都显示四组呼吸。测试结束时模式、全亮亮度和逐灯参数与测试前相同。呼吸相位由界面生成。另在 WebGL 和软件渲染两条路径验证了三视图、连线投影与机身离线时的显示。

0.6.0 的快捷键编辑器已验证单独录入 Esc、Ctrl 加 Esc、虚拟键盘组合键的选中与取消、保存后重新打开，以及语音快捷键编辑。Windows 桌面端已从「试聚焦聊天框」确认 Codex、DeepSeek Harness 和 WorkBuddy 的输入焦点。DeepSeek 同时显示搜索框和消息框时，焦点落在消息框。WorkBuddy 通过系统辅助功能确认编辑控件的焦点状态。豆包工作台和 Claude 已配置识别规则，仍待安装对应客户端后实测。上述聚焦测试均未向工作台发送消息。

## 2026-11-20 微信输入法与记事本联测

实际控制设备的进程为 0.3.0，已安装的 0.3.1 仅用只读观察命令核对原始报告。测试起止检查均未发现 UlanziDeck 进程。机身在线，接收器报告电量 90%。应用选择 AU05 麦克风，配置为微信输入法、按住 Ctrl + Win 触发。

专用空白记事本中出现含「AU05设备」的中文。测前记录基线后，主程序新增两次正常结束的 K1 会话，时长为 2.152 秒和 7.446 秒。后一轮在设备观察窗口内只有一个 K1 down 和一个 K1 up，两者相隔 7.450 秒。上述时长均指按住时间。中文已进入目标输入框，识别延迟、逐字准确率及微信输入法实际使用的音频端点需另行核对。

同句对照中，用户确认实体键盘按住 Ctrl + Win 没有出字，按住 AU05 语音键则在记事本得到「今天下午3点开会」。该次设备观察到 K1 down、up 各一次，间隔 2.655 秒，主程序记录 2.656 秒且正常结束。微信输入法进程版本目录为 3.0.2.44。按键设置中的 Ctrl + Win 是 AU05 Desk 请求发送的组合；微信输入法自身的实际绑定、键盘侧未出字的原因及语音浮窗是否出现均未验证。

## 发布内容与迁移

桌面程序和 WebView2 加载器同目录，安装包附源码、许可与说明。宿主继续读取已有配置、历史、授权和统计；新增的 au05_hid 表只保存本机校准。用户从旧版迁移时可启用直接订阅按键，也可另行校准标准 HID 控件。正式版本由 GitHub Releases 分发。

0.3.1 的发布构建通过 11 项 Rust 测试及配置导出测试。对编译后的前端使用模拟设备状态在 Chromium 核对了首次引导、跨页保持测试模式、回眸加载、另存常用语、完成条件和跳过流程。已从 NSIS 包提取程序，验证对应源码、四个本机 HID 集合、AU05 麦克风枚举及 MCP 的版本回复。后续观测时本机 UlanziDeck 已重新启动，因此该时段不用于证明独占或独立运行。
